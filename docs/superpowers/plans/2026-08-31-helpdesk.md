# In-app Helpdesk with Explicit IT Backlog Routing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an authenticated native helpdesk for user-facing support requests, with a shared operational queue, ticket conversations, screenshot attachments, and explicit staff-controlled GitHub backlog routing while preserving the existing IT backlog workflow.

**Architecture:** Add shared Zod contracts and Prisma models for `HelpdeskTicket`, `HelpdeskComment`, and `HelpdeskAttachment`. A NestJS `HelpdeskModule` owns requester ownership, the shared support queue, status transitions, audit records, and best-effort GitHub synchronization. The portal uses a single authenticated `/helpdesk` route with the existing MyDAUST shell and design-system primitives; the existing `/it/backlog` page remains separate and unchanged.

**Tech Stack:** Node 20+, pnpm 10.23.0, NestJS 11, Prisma 6.2.1/PostgreSQL, API-local Zod 3.24, shared ESM Zod contracts, Next.js 15 App Router, React 19, Vitest 4, TypeScript strict mode.

## Global Constraints

- The helpdesk is the system of record for support tickets; GitHub Issues remains the engineering backlog system of record.
- Only support roles `registrar`, `admissions`, `dining`, `it_admin`, and `admin` can access the shared queue and management endpoints.
- All routes remain authenticated unless explicitly marked otherwise; no anonymous/public submission is added.
- API bodies are received as `unknown` and parsed with the API-local Zod instance because the API has no global `ValidationPipe` and uses the CJS/ESM Zod compatibility filter.
- Status transitions are exactly: `new → in_progress`, `new → waiting_on_requester`, `in_progress → waiting_on_requester`, `in_progress → resolved`, `waiting_on_requester → in_progress`, `waiting_on_requester → resolved`, and `resolved → in_progress`.
- Student requests are forced to the authenticated student’s own `Student.id`; parents may select only a child linked through `GuardianStudent`; staff may submit without a student.
- Requesters cannot change status, priority, category, routing type, or assignment and cannot see internal notes.
- Attachments are screenshots/images accepted by the existing magic-byte uploader, use the existing `MAX_UPLOAD_BYTES` limit, and require ticket-scoped authorization before metadata or bytes are returned.
- GitHub credentials are server-only; the API is allowed to boot without them. Missing configuration or failed issue creation keeps the local ticket valid with a visible retryable sync state.
- Internal comments never generate notifications. Mail is attempted only when the existing `notifications.emailEnabled` AppSetting is true.
- Every protected ticket mutation writes an inline `AuditLog`; transactional mutations use `tx.auditLog.create`.
- The existing MyDAUST tokens, typography, `PageHeader`, `Card`, `Badge`, `Button`, `Field`, `Input`, `Select`, `Modal`, and existing sidebar shell are reused; no new portal area or role is added.
- Agent-authored work uses the conventional-commit subject suffix `(AI-generated)` if a commit is requested later; no commit, branch, push, or merge is performed in this session unless the user explicitly requests it.

```prisma
enum HelpdeskCategory {
  admissions
  academics
  student_affairs
  it_portal
  other
}

enum HelpdeskPriority {
  low
  normal
  high
}

enum HelpdeskStatus {
  new
  in_progress
  waiting_on_requester
  resolved
}

enum HelpdeskRoutingType {
  support
  engineering
}

model HelpdeskTicket {
  id                 String                @id @default(uuid())
  requesterId        String
  requester          Person                @relation("HelpdeskRequester", fields: [requesterId], references: [id], onDelete: Restrict)
  studentId         String?
  student            Student?              @relation("HelpdeskStudent", fields: [studentId], references: [id], onDelete: SetNull)
  assigneeId        String?
  assignee           Person?               @relation("HelpdeskAssignee", fields: [assigneeId], references: [id], onDelete: SetNull)
  title              String
  description        String
  category           HelpdeskCategory
  priority           HelpdeskPriority       @default(normal)
  status             HelpdeskStatus         @default(new)
  routingType        HelpdeskRoutingType    @default(support)
  githubIssueNumber  Int?
  githubIssueUrl     String?
  githubSyncState    String                 @default("pending")
  githubSyncError    String?
  githubSyncedAt     DateTime?
  resolvedAt         DateTime?
  version            Int                    @default(1)
  createdAt          DateTime               @default(now())
  updatedAt          DateTime               @updatedAt
  comments           HelpdeskComment[]
  attachments        HelpdeskAttachment[]

  @@index([requesterId, createdAt])
  @@index([status, createdAt])
  @@index([category, status, createdAt])
  @@index([routingType, githubSyncState])
  @@index([studentId])
  @@index([assigneeId])
}

model HelpdeskComment {
  id         String          @id @default(uuid())
  ticketId   String
  ticket     HelpdeskTicket  @relation(fields: [ticketId], references: [id], onDelete: Cascade)
  authorId   String
  author     Person          @relation("HelpdeskCommentAuthor", fields: [authorId], references: [id], onDelete: Restrict)
  body       String
  isInternal Boolean         @default(false)
  createdAt  DateTime        @default(now())
  updatedAt  DateTime        @updatedAt

  @@index([ticketId, createdAt])
  @@index([authorId, createdAt])
}

model HelpdeskAttachment {
  id         String          @id @default(uuid())
  ticketId   String
  ticket     HelpdeskTicket  @relation(fields: [ticketId], references: [id], onDelete: Cascade)
  uploaderId String
  uploader   Person          @relation("HelpdeskAttachmentUploader", fields: [uploaderId], references: [id], onDelete: Restrict)
  url        String
  name       String
  size       Int
  mimeType   String
  createdAt  DateTime        @default(now())

  @@index([ticketId, createdAt])
  @@index([uploaderId, createdAt])
}
```
